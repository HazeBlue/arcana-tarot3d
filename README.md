# Arcana · 三维塔罗

一个基于 three.js 的沉浸式塔罗牌 Web 应用：完整 78 张牌铺成的无限环形牌阵、实时抽取三张牌、结合问题即时生成专属解读。

全部视觉资源（牌背曼陀罗、78 张牌面、光晕、星空、地面纹样）都由 Canvas 2D 在运行时程序化绘制，仓库内没有任何二进制美术资源，因此体积极小、风格完全统一，也便于自由换肤。

---

## 核心功能

### 1. 完整 78 张牌的无限环形牌阵

- 整副塔罗牌 78 张全部铺进牌阵，一张不少
- 步长被精确设为 360 / 78 度，让 78 张牌恰好铺满一整圈。由此得到两个关键性质：
  - 牌的序号与相对角度一一对应，环形滚动时永远不会有两张牌落在同一个角度上
  - 整副牌首尾天然相接，焦点索引没有上下限，永远不存在「滑到头」的状态
- 聚焦的那张牌会浮起、放大并点亮金色光晕；滑动时整副牌像轮盘一样连续滚动
- 选中后卡牌沿贝塞尔弧线飞向桌面上的「现状 / 转折 / 走向」三个牌位，落位瞬间喷发金色粒子，随后翻面
- 每张牌有约 34% 的概率为逆位，逆位牌会在牌面平面内真实旋转 180 度
- 牌面贴图按需生成：78 张牌在启动时只共用一张牌背贴图，翻开哪张才画哪张

### 2. 操作（鼠标与触屏统一）

项目只监听 Pointer Events，因此鼠标、触控板、手指三种输入走的是同一套代码，行为天然一致。

| 操作 | 作用 |
| --- | --- |
| 按住左右拖动 / 手指左右滑动 | 牌扇跟着手平移（按像素换算成张数，跟手而不跳格） |
| 松手 | 带惯性继续滑一段，然后自动对齐到最近的一张牌 |
| 点击 / 轻点某张牌 | 直接把它抽出来，不用先对齐再确认 |
| 点击 / 轻点空白处 | 抽出当前正对镜头的那张牌 |
| 鼠标停在某张牌上 | 那张牌被抬到正中并点亮 |
| 上下拖动 | 抬高 / 压低镜头 |
| 滚轮 | 推近 / 拉远 |
| ← / → 或 A / D | 键盘浏览，长按可连续滑动 |
| 空格 / 回车 | 抽出正对镜头的那张牌 |

几处必须踩对的细节：

拖拽要按像素换算成小数张数再累加，而不是每拖一段就跳一格。焦点索引因此允许是小数，
松手时再吸附到整数。若只在整数上累加，拖动会变成一顿一顿的跳格。

悬停聚焦必须加「指针真的移动过一段距离」的条件。牌扇是六成重叠的密集排列，
聚焦一变就有牌从光标下方滑过，不加限制会形成「换牌 → 焦点跳 → 再换牌」的往复横跳。

浏览步长取 5 而不是 3：在一圈 78 张牌里以 N 为步长跳跃，只有当 N 与 78 互质才能遍历全部 78 张；
取 3 会退化成只循环访问 26 张，剩下 52 张永远翻不到。这个 bug 不报错、不崩溃，
只有统计「实际覆盖到的牌数」才能发现。

### 3. 解读

一份解读按下面的结构生成，最想知道的判断放在最前面：

1. 先说结论 —— 直接给出倾向性判断，不绕弯
2. 牌面 —— 三张牌与正逆位一览
3. 逐张细读 —— 每张牌分「画面 / 在这件事上 / 提示」三段
4. 三张牌之间的关系 —— 元素构成、主题牌分量、起点与落点之间的落差
5. 时间与行动窗口 —— 按走向牌的元素给出节奏快慢（周 / 月 / 季度），并按正逆位判断是否会顺延
6. 能量评估 —— 正位比例与主题牌占比合成的沟通度
7. 行动建议与需要留意

文本按三层叠加组装，这是让结果不像模板的关键：

- 画面层：每张牌一句专属的画面描述。56 张小阿卡纳全部手写，对应韦特牌面上真实画着的场景
- 位置层：这张牌落在「现状 / 转折 / 走向」哪一格意味着什么
- 领域层：把牌义翻译到用户真正的语境里（十个问题类别 × 五个元素）

问题会先被归类（感情 / 事业 / 财运 / 学业 / 身心 / 人际 / 抉择 / 成长 / 内在 / 综合）
并识别提问类型（是非 / 选择 / 趋势 / 开放），再依此选择措辞。

分类用「强关键词 + 弱关键词」两档权重：「关系」「如何」「怎么」这类词几乎什么问题里都会出现，
描述的是提问的形式而不是主题。它们被降权一半，只做兜底——否则「我和他这段关系接下来会怎么走」
这种明显的感情题会被整句判成「抉择」。

### 4. 可复现的解读

解读文本使用「问题 + 牌组」哈希作为种子随机数。同一个问题配同一组牌，无论刷新多少次措辞都一致，
用户截图分享或回看不会对不上；而不同问题之间的行文依然多样。

### 5. 视觉表现

- 深空黑底 + 香槟金描边 + 玻璃拟态面板
- UnrealBloomPass 泛光通道，只有金色描边与光晕溢出
- 程序化「暗色影棚」环境贴图（黑色房间 + 暖金 / 幽紫 / 暖橙三块发光板），让金属只反射金紫色光斑而不是一片惨白
- ACES 电影级色调映射、指数雾、星空三层视差、星云、空气浮尘、地面光池
- 竖屏自动切�换取景：拉远、抬高、放宽视野，并收窄三个牌位间距

## 运行

```bash
npm install
npm run dev
```

浏览器打开 http://localhost:5173 即可。

源码使用 ES Module，需要通过 HTTP 访问，因此请用 `npm run dev` 而不是直接双击 index.html。

打包静态产物：

```bash
npm run build
```

产物在 `dist/`，可直接部署到任意静态托管。

## 一些实现上的取舍

牌面贴图按需生成
78 张牌若在启动时全部绘制，需要约 200MB 显存。因为牌背朝上时整副牌只需要一张共用贴图，所以牌面被推迟到翻开前一刻才画。启动显存占用降到可忽略，代价是翻开瞬间会有约 20 毫秒的绘制开销。

材质共享
78 张牌如果每张都持有自己的材质，会产生 150 多个 MeshPhysicalMaterial 实例。牌体、牌背、以及未翻开时的牌面占位都做成整副共用的单例，每张牌只在真正翻开时才建立一份带贴图的独立牌面材质。

射线拾取只测牌背平面
鼠标悬停需要知道光标下面是哪张牌。牌体的挤出几何体有几百个三角形，逐帧对 20 张可见牌求交开销可观；而牌背只是个两三角形的平面，用它当碰撞面既准确又几乎免费。

ExtrudeGeometry 的倒角会改变厚度
开启 bevel 后卡牌的实际 Z 跨度是 `depth + 2 × bevelThickness`，而不是 `depth`。牌面与牌背平面必须贴在真实半厚度之外，否则会被牌体吞掉，表现为「牌背永远显示为一块纯金板」。

透明物体永远最后绘制
星云是半透明加色混合材质，会排在所有不透明物体之后渲染。因此它的 `depthTest` 必须开启，否则会穿透桌面糊在画面前景。
